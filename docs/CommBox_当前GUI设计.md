## 2. 功能清单

**连接**：串口 / TCP / UDP / 串口服务器 / HTTP 客户端五种工作模式。TCP、UDP 与串口服务器可切服务端或客户端；协议选择仅串口服务器可改。自动重连可关，间隔可调。最近连接下拉框回填全部参数。

**数据监控**：表格列为时间、方向、HEX、ASCII、长度，协议 / 来源 / 连接 ID 三列默认隐藏（右键打开）。筛选一行：关键字、方向、显示模式、协议、时间范围。保留最新 10000 条，完整历史落 SQLite。可清空、保存 TXT、导出 CSV、AI 分析。

**发送**：HEX 或文本、行尾、目标（默认广播 / 定向到某客户端 / UDP 指定地址）、发送后清空、验证（显示字节数与原始 HEX）、历史与快捷（收藏）下拉、定时发送、循环发送（次数 0 为持续）。定时与循环固定使用启动那一刻的数据和目标。

**客户端列表**：右键可定向发送、仅看该客户端、断开、复制地址、清空显示统计。同 IP 不同端口按独立会话管理。

**工具**：HTTP 工作台（含 cURL 导入导出）、校验与转换、连接管理（最大连接数与桥接回复策略）、串口服务器快捷切换、虚拟串口映射（开发中，仅说明状态）、历史数据分析。

**AI**：右侧面板默认隐藏，AI 默认关闭。设置服务后，只有主动分析或追问才提交所选数据。八个快捷分析按钮走本地规则或 AI。失败不影响通信。

**其他**：实时监控窗口、托盘常驻、多开（新建实例）、检查更新。

## 4. 布局规则（改界面前必读）

这几条是 lxn/walk 的实际行为，踩过才总结出来的，违反其中任何一条界面立刻走形。

**富余宽度会变成控件间距。** `BoxLayout` 把一行的富余宽度按 `权重 / 组内权重和` 分给能变宽的控件；定了宽度上限的控件拿不走自己那一份，剩下的会平摊成每个控件之前的位移——这就是"标签与它的下拉框之间空出 180px"的成因，与对齐方式无关（near 对齐只是把位移挪到控件之后）。三条对策：

1. 行里有 greedy 控件就够了：可编辑 `ComboBox`、`LineEdit`、`TextEdit`、`ListBox`、`TableView` 本身是 greedy，会先吃掉富余；
2. 没有就补 `HSpacer{}`，它是 greedy spacer，排在非 greedy 控件之前结算；
3. 必须让某个非 greedy 控件（如不可编辑下拉框）撑满时，给它 `StretchFactor: stretchFill`（=100）。

**带省略号的 Label 可压缩，但也撑不满。** `EllipsisMode: EllipsisEnd` 让 Label 变成 `ShrinkableHorz`，最小宽度归零——状态栏、数据统计、发送提示、客户端标题都靠这条才不会用文字宽度顶住整窗最小宽度。代价是它的宽度上限等于文字本身宽度，撑不满一行，所以这类 Label 后面仍要跟 `HSpacer{}`。

**`MaxSize` 同时压低最小宽度。** `minSizeEffective` 会用 `MaxSize` 截断最小宽度，因此给控件定上限既能防拉伸，也能防它把窗口最小尺寸顶大。定宽控件一律 `MinSize` 与 `MaxSize` 取同值。

**隐藏控件不占位。** `SetVisible(false)` 的控件被排除在布局之外，所以成对的标签与控件必须一起显隐（协议、角色、端口、UDP 目标都是这么处理的），否则栅格会留空行。

**每秒轮询不要无条件回写控件。** `SetModel` / `SetText` 触发重排，而 Windows 重排时会强制关掉正在展开的下拉列表。`statsLoop` 里所有写回都先比对上一次的值（`lastFooter`、`lastPeerLabels`、`lastDetails` 等）。

**尺寸基线**（`windows/main.go` 常量）：正文 10pt、分区标题 12pt 加粗、等宽 10pt；输入类控件 `rowH` = 28px，按钮 `btnH` = 30px。定宽按"图标 24 + 每汉字约 13px + 内边距 20"估，两字按钮 70、四字 96、带图标四字 128。标签一律 `AlignHNearVCenter`，否则文字贴在输入框顶部。

## 6. 构建与发布

```bash
go test ./...                                                   # 全量测试
go build -ldflags="-H windowsgui -s -w" -o build/CommBox.exe ./windows
```

`windows/rsrc_windows_amd64.syso` 提供清单与图标（含 PerMonitorV2 DPI 感知），Go 构建自动链接，不能删。发布包为 `CommBox.exe` + `README-Windows.txt` 打成 `CommBox-<版本>-Windows-x64.zip`，另单独挂一份裸 exe。

发布步骤：改 `internal/wincore/modes.go` 的 `Version` → 构建 → 打包并算 SHA256 → 写 `docs/release-v<版本>.md` → 提交并打 tag → push → 用 GitHub API 建 Release 并上传两个资产。

**发布说明有一条硬约束**：正文必须保留 SHA256 代码块，格式为 `<64 位小写十六进制><两个空格><文件名>`。更新器就是从发布说明里解析这一行来校验下载的安装包（`sha256FromNotes`），删掉它下载就没有校验。说明本身保持精简：标题、本版变化、校验、注意四节即可——更新对话框直接显示这段文字，620×520 的窗口读不完长篇。

## 7. 测试现状

`go test ./...` 覆盖引擎（连接、重连、定向发送、桥接、存储、统计、HTTP、cURL、分析、工具箱）与 Windows 侧的纯函数（报文格式化、筛选、AI 范围选择、HTTP 拼装、更新文案）。更新模块另有 11 个用例覆盖版本比较、发布信息解析、安装包挑选、下载域名白名单、SHA256 解析与校验失败清理。

联网用例默认跳过，手动跑：

```bash
COMMBOX_LIVE_UPDATE=1 go test -count=1 -v -run TestLiveUpdateDownload ./internal/wincore/
```

GUI 没有自动化测试。界面改动靠实机核对：启动后按三种尺寸（默认、最小、最大化）各截一次图，逐行检查有没有重叠、截断或空档，串口模式与 AI 面板展开各看一次。

## 8. 已知限制与后续候选

限制：Windows 虚拟串口未开放（com0com 的驱动安装、串口命名、命令超时三项未在真机验证通过）；数据表表头中文在等宽字体下字距偏开（表头与单元格无法分别设字体，而 HEX 列需要等宽）；布局只在 175% 缩放下逐项核对过；未做代码签名，SmartScreen 会提示未知发布者；macOS / Linux 近几版未构建验证。

值得做的下一步：更新对话框的下载按钮尚未做点击级实测（下载链路本身已用联网用例跑通）；配置导入导出（把连接参数与收藏搬到另一台机器）；数据表列宽记忆；深色模式；发送区快捷键（如 Ctrl+Enter 发送）；虚拟串口在真机上补完后重新开放。
