# CommBox v0.8.0 全部功能与 GUI 优化设计

> 文档定位：CommBox v0.8.0 功能与 GUI 设计基线  
> 当前基线版本：v0.7.9  
> 设计目标版本：v0.8.0  
> 更新日期：2026-09-12  
> 核心定位：开箱即用的工业通信调试与通信诊断工具  
> AI 定位：可选增强能力，默认关闭，不影响任何本地通信与本地分析功能

---

## 1. 文档说明

本文档在 CommBox v0.7.9 当前实现基础上，统一整理 v0.8.0 的功能优化、GUI 优化及新增功能。

### 1.1 状态说明

| 标记 | 含义 |
|---|---|
| 已有 | v0.7.9 已实现 |
| 优化 | 在现有能力基础上改进 GUI、交互或能力 |
| 新增 | v0.8.0 建议新增 |
| 明确 | 对现有/规划能力进一步明确行为边界 |

### 1.2 v0.8.0 核心原则

1. **通信优先**：CommBox 首先是一款通信调试工具，实时数据区始终是主界面核心。
2. **本地优先**：CRC、Modbus 字段、数值转换、响应时间、统计等确定性工作优先在本地完成。
3. **分析增强**：从“收发工具”升级为“通信诊断工作台”。
4. **AI 可选**：AI 默认关闭，不成为串口、TCP、UDP、HTTP、SQLite、本地分析等功能的依赖。
5. **结果可追溯**：分析结论尽量可以定位到原始报文、Connection、时间范围和请求生命周期。
6. **操作简洁**：主界面避免堆叠入口，最大面积留给实时数据。
7. **跨平台一致**：macOS / Windows 尽量保持相同的功能结构和操作逻辑。

# 9. 串口服务器

## 9.1 核心模型【重点】

串口服务器定义为：

> **一个 Serial COM 端口映射一个 TCP 监听端口；Serial COM 只打开一次，映射后的 TCP 监听端口允许同时运行多个独立 TCP Connection。所有 Connection 共享该串口进行双向通信。**

示例：

```text
Serial COM3
9600 / 8N1
       │
       ▼
┌─────────────────────────┐
│ CommBox Serial Server   │
│ TCP 0.0.0.0:5000        │
└────────────┬────────────┘
             │
             ├─ Connection #1
             │  192.168.1.101:52130
             │
             ├─ Connection #2
             │  192.168.1.101:52131
             │
             ├─ Connection #3
             │  192.168.1.102:53001
             │
             └─ Connection #N
```

不是：

```text
COM3 → TCP :5000 → 只能一个连接
```

而是：

```text
COM3 → TCP :5000 → N 个 TCP Connections
```

## 9.2 Connection 行为【明确】

- COM3 只打开一次。
- TCP 监听端口支持多个并发 Connection。
- 同一 IP 可以同时建立多个 Connection。
- 每个 Connection 通过独立 TCP 会话/远端端口区分。
- 每个 Connection 独立统计 RX/TX。
- 单 Connection 断开不影响 COM3。
- 单 Connection 断开不影响其他 Connection。
- 停止串口服务器时统一关闭所有 Connection。

## 9.3 NET → Serial【优化】

多个 TCP Connection 发来的数据统一进入串口发送流程：

```text
Connection #1 ─┐
Connection #2 ─┼──→ Serial COM3
Connection #3 ─┘
```

要求：

- 一个网络报文作为完整串口写入单元。
- 不允许不同 Connection 的字节交叉写入串口。
- 建议加入串口发送队列。
- 对 Modbus RTU 等请求/响应协议，后续支持请求串行化。

## 9.4 Serial → NET【优化】

支持策略：

```text
● 广播到所有 Connections
○ 仅发送到最近请求 Connection
```

默认建议：

```text
广播到所有 Connections
```

# 11. cURL 支持

## 11.1 导入 cURL【新增】

允许粘贴：

```bash
curl -X POST 'http://192.168.1.100:8080/api/data' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer xxx' \
  --data-raw '{"deviceId":"001","value":25.6}'
```

自动解析到：

- Method。
- URL。
- Query Params。
- Headers。
- Authorization。
- Cookie。
- Body。
- Form。
- Timeout。
- 重定向行为。

解析后由 CommBox HTTP Client 发起请求，不直接调用系统 shell。

## 11.2 cURL 参数【新增】

```text

-F / --form
-b / --cookie
-u / --user
-A / --user-agent
--connect-timeout
-m / --max-time
-k / --insecure
-L / --location
```

## 11.3 生成 cURL【新增】


```text

   ↓

   ↓

   ↓

   ↓
```

```text
   ↓
对比分析
   ↓
验证
   ↓
最终结论
```

```text
 ↓
建议减少 Connection 测试

第 7 轮
```

# 70. v0.8.0 最终定位

CommBox v0.8.0 不再只是：

```text
串口助手
```

也不应该变成：

```text
AI 聊天工具
```

建议定位为：

> **CommBox 是一款开箱即用的工业通信调试与通信诊断工作台，支持串口、TCP、UDP、串口服务器、HTTP/cURL、实时数据监控、SQLite 历史分析、本地协议分析以及可选 AI 深度诊断。**

核心能力：

```text
实时通信
    +
多 Connection
    +
历史数据
    +
本地确定性分析
    +
AI 深度诊断
```

AI 的最终位置：

```text
CommBox
│
├── 核心通信
│   ├── Serial
│   ├── TCP
│   ├── UDP
│   ├── Serial Server
│   └── HTTP / cURL
│
├── 核心分析
│   ├── 实时数据
│   ├── SQLite
│   ├── Modbus
│   ├── CRC
│   ├── 请求 / 响应
│   └── 数值 / 大小端
│
└── AI 增强
    ├── 自动诊断
    ├── 多项诊断
    ├── 多轮交互
    ├── 追加数据
    ├── 多 Connection 对比
    ├── HTTP / cURL 诊断
    ├── 排查建议
    └── 验证闭环
```

最终原则：

> **没有 AI，CommBox 仍是一套完整的专业通信调试工具；开启 AI 后，CommBox 升级为能够结合通信数据、历史记录、本地分析证据和多轮上下文进行问题诊断的智能通信诊断工具。**
