# CommBox v0.9.2

Windows x64，解压后运行 `CommBox.exe`。发布包附带 VirtualCOM v0.2.0 的图形界面和命令行，无需安装虚拟串口驱动。

## 本版变化

- 断开时日志写明是哪一端断的：本端主动断开、服务端断开、客户端断开还是链路中断，并附断开方式（收到 FIN / 连接被重置 / 读取超时）、对端地址、本次连接时长、收发字节与帧数和底层错误。同一条记录也写入 SQLite。
- 手动断开原先没有日志，现在也记一条，并写明本端是客户端还是服务端；没有客户端连进来的 TCP/UDP 服务端同样按服务端记录。
- 串口断开单独分类，只分本端关闭与设备断开（拔出、驱动移除或提供端退出）。

日志示例：

```
TCP 连接已断开:服务端断开 · 对端正常关闭(收到 FIN) · 服务端 10.0.0.5:502 · 持续 00:01:23 · 收 2.0 KB/3 帧 发 100 B/5 帧 · 底层错误 EOF
```

## 使用

先运行 `VirtualCOM-GUI.exe` 创建一对端口并保持运行，再打开两个 CommBox 窗口，分别连接两端。命令行使用 `CommBox-CLI.exe -list` 查看端口、`-port COM号` 打开。

## 验证与边界

- 全量 Go 与 Windows GUI 回归测试通过；发布产物逐项校验 PE 头、构建来源 commit、版本资源和压缩包内容。
- 断开来源用回环抓包核对过：服务端关闭、客户端关闭、手动断开和对端复位四种情况，日志报的断开方与先发 FIN/RST 的一方一致。
- 断开来源按操作系统返回的错误判断。经过 NAT、防火墙或代理时，中间设备发出的复位也会报成对端断开；识别不了的错误记为"断开来源未知"，不做猜测。
- VirtualCOM 适配的边界与 v0.9.0 相同：只提供字节流端口，波特率、数据位、校验、停止位和控制信号不生效，未适配的第三方串口软件仍不兼容。
- VirtualCOM 必须保持运行并与 CommBox 位于同一用户登录会话；退出后端口会移除。Windows 10 和长时间运行尚未验收。
- 程序未做商业代码签名。
