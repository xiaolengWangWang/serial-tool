# CommBox v0.8.2 — Windows 布局重排版

本次提供 Windows x64 桌面程序，解压后运行 CommBox.exe，无需安装 Go。

本版只调整 Windows 桌面版的界面布局与控件尺寸，不改动通信引擎、协议处理与数据存储逻辑。

## 布局调整

Windows 版此前按效果图排布，与 macOS 版（`desktop/app.m` 的 `layoutMainPanes`）差异较大。本版按 macOS 的三栏骨架重排，两端布局语言统一。

- 三栏宽度对齐 macOS：左栏 300px（原 250–270）、AI 面板 250px（原 330–350），中栏拿到其余空间。
- 移除顶部工具栏。原有五个按钮在菜单栏或数据监控标题行均已有等价入口（新建→文件菜单、清空/导出→标题行、AI 分析→标题行与查看菜单、设置→设置菜单）。
- 数据监控的筛选控件由四行合并为一行，全部改用下拉框，搜索框占据剩余宽度；报文条数并入标题行。
- 数据表新增协议 / 来源 / 连接 ID 三列的显示开关，默认隐藏。八列合计约 895px，而 AI 面板展开时中栏仅约 700px，全部显示会出现横向滚动条。需要时通过表格右键菜单打开。
- 数据表下方新增选中操作行：显示已选条数，提供全选 / 清除 / 反选 / 分析选中。此前 AI 面板已有"当前选中数据"这一分析范围，但主界面没有对应的选择入口和计数反馈。
- 发送区由六行压缩为三行，高度固定 190px（与 macOS 一致）；"验证"按钮移至发送按钮下方。
- 窗口宽度小于 1280px 时自动收起 AI 面板，保证中栏始终有足够宽度承载数据表。

经上述调整，1280×820 窗口下数据表可视高度由约 364px 增加到约 400px。

## 控件尺寸修正

walk 的水平布局会把未指定尺寸的控件按剩余空间均摊，与控件内容无关，因此出现了明显不合理的宽度。本版为相关输入框与下拉框指定尺寸（下列为 1280×820 窗口下的逻辑像素）：

| 控件 | 调整前 | 调整后 |
| --- | --- | --- |
| 发送区 行尾 | 245 | 76 |
| 发送区 历史 | 107 | 187 |
| 发送区 快捷 | 107 | 187 |
| 左栏 重连间隔 | 208 | 70 |
| 筛选 显示模式 | 92 | 112 |
| 筛选 协议过滤 | 70 | 94 |
| 筛选 时间过滤 | 59 | 84 |
| 筛选 方向过滤 | 60 | 78 |

## 验证

- Windows 下 `go test ./...`、`go vet ./windows`、`gofmt -l windows` 与桌面构建均通过。
- 通过 UIAutomation 读取运行中窗口的实际控件坐标，逐项核对三栏宽度、各行高度与全部输入框 / 下拉框尺寸。筛选行右边界 1261px、发送区第三行右边界 1253px，均在 1280px 窗口内不溢出。
- 桌面程序启动正常，标题显示 CommBox v0.8.2 · Windows。

## 已知限制

- 布局核对在 175% 显示缩放的环境下进行，实际渲染尺寸按该缩放比换算为逻辑像素。其他缩放比例下未逐项复核。
- AI 面板展开状态下的布局未做实测，面板默认关闭，本次核对基于默认状态。
- Windows 虚拟串口仍不可作为已验证功能使用，此前的 CNCA1 打不开及 com0com 驱动管理命令超时问题本版未修复。
- 本次未构建或验证 macOS / Linux 程序。
- Windows 程序未做商业代码签名。
