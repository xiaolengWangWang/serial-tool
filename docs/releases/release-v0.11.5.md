# CommBox v0.11.5 — 现场排查提示与 Modbus 本地检查修复

本版修复本地检查把 Modbus 应答当成请求解析的问题，并在 Windows 版加入四项现场排查提示，对应现场最常见的几类问题：认不出转换线、发了没回应、设备拒绝请求、串口打不开。

## 修复

- 本地检查把读寄存器的应答当成请求来解析：`01 03 02 00 64 B9 AF` 被显示成“起始地址 512，数量 25785”，现在正确显示为数据字节数 2、寄存器值 100。数据类型候选改为取寄存器数据，不再取帧头字节；请求帧不再给出没有意义的候选。
- 串口被占用或不存在时，原来只提示“操作失败”，现在写明端口和处理办法。

## 现场排查提示（Windows）

- 串口下拉在端口名后附设备名称，如“COM5  USB-SERIAL CH340”，多个端口时一眼认出转换线；VirtualCOM 端口标为“VirtualCOM 免驱动”。
- 串口、TCP 客户端、UDP 客户端模式下手动发送后，1 秒内没收到数据，发送区下方按模式提示排查方向，如“核对站号、串口参数、A/B 线和 CRC”。
- Modbus 异常应答（如 `01 83 02 C0 F1`）在数据表中标红，HEX 后附异常码含义，如“异常应答 02：非法数据地址”；发送区下方同时显示完整说明。可在搜索框按含义查找。
- 打不开串口时提示“COM5 正被其他程序占用”或“找不到 COM5”，并说明下一步怎么做。

## 本地分析

- Modbus 帧区分请求与应答：请求列出起始地址与数量，读寄存器应答列出各寄存器值，写多个寄存器的请求列出数据，异常应答给出异常码含义。
- 串口服务器透传时，TCP 上的 Modbus RTU 帧按 CRC 识别。
