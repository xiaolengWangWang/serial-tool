# VirtualCOM v0.2.0

Windows x64，解压后运行 `VirtualCOM-GUI.exe`（图形界面）或 `VirtualCOM.exe`（命令行），无需安装，不需要管理员权限。

自研虚拟串口，纯用户态实现：不安装驱动、不需要任何签名、不依赖第三方组件。

## 本版变化

**新增图形界面** `VirtualCOM-GUI.exe`，布局按功能规格第 3 节：

- 一对串口一张卡片，两端对称展示端口号、状态、占用程序与 TX 字节数，中间是 `⇄` 配对标识
- 每张卡片带 `详情`、`修改编号`、`禁用/启用`、`重启`、`删除`；删除前会列出将要删掉的两个编号让你确认
- 底部显示串口对与虚拟端口数量，以及全局 `诊断` 和 `刷新`
- 没有串口对时显示空状态与创建入口
- 命令行参数 `--pair COM10:COM11` 可重复，用于带预设串口对启动

与规格的两处差异，都因为本版没有驱动：顶部的「驱动状态」改成「实现方式：用户态（无驱动）」，不装驱动却显示驱动状态是假信息，点击它可以看实测的兼容性边界；「更多 ⋯」展开成一排文字按钮，规格本就要求删除用文字标识而非图标。

**修复两个状态显示缺陷**，都是界面跑起来才暴露的：

- 空闲端口被显示成「无法确认占用状态: Element not found.」。管道处于监听态时 `GetNamedPipeClientProcessId` 返回的是 `ERROR_NOT_FOUND`，不在原先的「明确未连接」判定里，于是走了兜底分支，满屏假告警。原有测试只覆盖了「使用中」，漏掉空闲这一半，现已补上回归测试。
- 卡片右半边与后三个按钮被挤出视口。原先用重复字符拼分隔线，120 个字符把卡片最小宽度撑得比窗口还宽。改用带边框的卡片容器，既解决溢出，也正好是规格要的卡片外观。

**启动时自动清理残留编号**。上次崩溃或被强杀后，COM 名会留在系统里而管道已不存在，用户只会看到「编号被占用」却查不出原因。GUI 与 `run` 启动时静默清理并把结果写进诊断报告；只清目标指向本项目管道、且管道确实已不存在的链接，不会误删另一个运行中实例的编号。

## 兼容性边界（请先读这一段）

本版把虚拟端口实现为**字节流管道**，不是真正的串口设备。以下为真机实测结果：

**能用**：`CreateFile` 打开、`ReadFile` / `WriteFile` 收发、Overlapped 异步 I/O、`CancelIoEx` 取消、跨进程打开、占用程序与 PID、端口重复打开关闭、多组互不串扰。

**不能用**：`GetCommState` / `SetCommState` / `SetCommTimeouts` / `SetCommMask` / `WaitCommEvent` / `PurgeComm` / `ClearCommError` 全部返回 `ERROR_INVALID_FUNCTION`；`GetFileType` 返回 `FILE_TYPE_PIPE` 而非 `FILE_TYPE_CHAR`；无波特率、数据位、校验、停止位设置；无 RTS / CTS / DTR / DSR / DCD / BREAK；设备管理器与 `SerialPort.GetPortNames()` 不显示这些端口。

**直接后果**：凡是用 .NET `SerialPort`、pyserial、`go.bug.st/serial` 打开端口的软件，会在打开阶段直接失败。只有把端口当字节流读写的程序能配合本版使用。

原因是内核里的命名管道驱动不处理串口 IOCTL，用户态代码无法改变这一点。要消除上述限制必须安装内核驱动，而 Windows x64 只加载带可信签名的驱动——这与本版「不装驱动、不签名」的选型互斥。

## 注意

- **进程退出后虚拟端口随即拆除**，通信中断。GUI 退出后继续工作、系统重启后自动恢复，本版均未实现。
- 进程被强杀时残留的编号会在下次启动时自动清理，也可以手工执行 `VirtualCOM.exe cleanup`。
- 仅在 Windows 11 x64 上完成验收，Windows 10 x64 尚未验证。
- 未做长时间运行测试。
- 程序未做代码签名，SmartScreen 可能提示未知发布者。
- **杀毒软件可能拦截图形界面程序**。实测 360 企业版会直接隔离删除「剥掉符号的 GUI 子系统程序」——那是加壳投放器的典型特征。本版因此保留符号信息构建 GUI（体积从 5.7 MB 增至 8.5 MB），实测不再被拦。若仍被拦截，请在安全软件里加入信任，或改用命令行版 `VirtualCOM.exe`（未被拦截）。
