# CommBox v0.8.3 — 下拉框修复与界面细节

本次提供 Windows x64 桌面程序，解压后运行 CommBox.exe，无需安装 Go。

本版修复一处影响日常操作的界面缺陷，并继续调整 Windows 桌面版的布局、字体与配色。通信引擎、协议处理与数据存储逻辑未改动。

## 修复

**所有下拉框刚展开就被收起。** 状态轮询每秒执行一次，其中无条件调用 `SetModel` 重建发送目标与客户端列表的数据源，并重设状态栏、客户端标题和连接信息三处文本。这些写入都会触发布局重排，而 Windows 在重排时会强制关闭正在展开的下拉列表，因此任何下拉框都撑不过一秒，来不及选中。

改为先比对内容，只有真正变化时才写回控件。修复后下拉列表展开可持续保持，实测连续五秒跨越五次轮询未被关闭。

## 界面

- 新增启动时贴合工作区：窗口按可用区域的 85% 收敛并居中。此前 1280x820 在高缩放比的屏幕上换算后接近满屏，底部的发送区可能被任务栏遮挡。最小尺寸由 1120x760 放宽到 1000x640，小屏才能正常收纳。
- 网络参数改为两列栅格，与串口参数一致，每个字段省下一行；协议与角色的标签随控件一同显隐，避免栅格中出现空行。左栏内容不再需要滚动才能看到"最近连接"。
- 成对的标签与控件收进子容器。此前水平布局把可用宽度平均切分给各控件，控件在各自槽位内左对齐，导致标签与其下拉框之间空出约 180 像素。调整后"行尾"与其下拉框间距为 13 像素，选中操作行的按钮之间基本相邻。
- 发送区的历史与快捷两个下拉框此前没有任何标签，界面上只是两个空白框，现已补上。
- 方向与时间两个筛选框原本都显示"全部"，无法分辨，改为"全部方向"与"全部时间"。
- 连接状态由居中改为左对齐，与上方表单对齐。

## 字体与配色

- 分区标题由 12pt 降为 10pt，与正文只差 1pt；提示文字由 8pt 提为 9pt。
- 等宽字号统一为 9pt：数据表、发送框与监控窗口此前不一致，同一条报文在两处显示大小不同，不便对照。状态栏也改用等宽字体，数字对齐。
- 原有深蓝、灰蓝、亮蓝三种蓝色并存，统一为一种主色。AI 面板的紫色字与淡紫底与整体配色冲突，一并改为主色与中性底。
- 窗口底色由偏蓝的浅色改为中性灰，状态色降低饱和度。

## 代码清理

移除从未被赋值或调用的死代码：模式按钮数组 `modeButtons` 及其两处遍历、`switchMode`、`toggleHexView`，以及 `loopSend`、`receiveEdit`、`hexView` 三个未使用字段。

## 验证

- Windows 下 `go test ./...`、`go vet ./windows`、`gofmt` 与桌面构建均通过。
- 通过 UIAutomation 读取运行中窗口的实际控件坐标核对布局：窗口 1243x736 逻辑像素，各行最右边界 1225，未超出窗口宽度。
- 下拉列表展开后连续五秒未被关闭，确认修复生效。

## 已知限制

- 发送区"目标"标签与其下拉框之间仍有约 43 像素间距，未能进一步收紧。
- 数据表表头的中文在等宽字体下字距偏开。表头与单元格无法分别设置字体，而 HEX 列需要等宽对齐，因此保留当前取舍。
- 布局核对在 175% 显示缩放下进行，其他缩放比例未逐项复核。
- AI 面板展开状态下的布局未做实测，面板默认关闭。
- Windows 虚拟串口仍不可作为已验证功能使用，此前的 CNCA1 打不开及 com0com 驱动管理命令超时问题本版未修复。
- 本次未构建或验证 macOS / Linux 程序。
- Windows 程序未做商业代码签名。
