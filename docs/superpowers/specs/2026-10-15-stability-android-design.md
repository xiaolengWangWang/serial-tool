# CommBox 稳定性与安卓版设计

日期：2026-10-15。基线：`v0.11.6`（`083a384`）。

## 目标与已确认范围

用户希望先排查现有桌面版的稳定性和架构，再提供操作方便的安卓版。安卓版由用户自行安装 APK，适配手机和平板，首版包含 USB OTG 串口、经典蓝牙 SPP、BLE、TCP/UDP 的基本收发、可编辑的 Modbus 常用指令，以及应用内检查、下载和安装更新。“手册尺寸”按“手机尺寸”理解；如不是此意，调整布局目标。

现有桌面版没有指定故障，因此稳定性工作以可复现的缺陷为准。基线 `go test ./...`、`go vet ./...` 和 `go test -race ./core` 均通过。项目当前无 Android 工程；本机未检测到 Android SDK、`adb` 或 Gradle。

## 交付顺序

1. **桌面稳定性排查**：以现有 Go `core` 的连接、被动断开、自动重连、并发发送和 SQLite 记录链路为重点，使用可控的本地端点复现故障。发现缺陷时先留下可失败的回归检查，再在共用路径修复。没有证据的问题只记录，不重写现有引擎。
2. **安卓版基础收发**：建一个独立的 Kotlin/Jetpack Compose Android 模块，实现统一会话状态与 USB、SPP、BLE、TCP、UDP 接入层。先完成设备发现、连接、收发、断开和手机/平板布局。
3. **现场功能与交付**：加入 Modbus 模板、连接配置记忆和本地日志；接入 APK 更新和签名构建，验证真机连接与更新流程。

三个阶段分别验收。安卓版依赖稳定的连接状态模型，但不要求先对桌面端作大规模重构。

## 架构选择

安卓版使用 Kotlin 原生界面和 Android 平台 API。`core` 当前直接依赖桌面串口库、PTY 和 SQLite 实现；通过 gomobile 绑定整个引擎会迫使这些依赖一起进入 Android，USB 与蓝牙仍要原生桥接。首版保留桌面 Go 引擎，通过相同的报文语义和共享测试向量校验 Modbus RTU/TCP 编码结果，不引入跨语言运行时。以后若确认有足够多的纯协议逻辑值得共用，再单独抽取，不为预期复用预先拆分引擎。

Android 内部保持四个边界：

- **连接适配器**：USB、SPP、BLE、TCP/UDP 各自负责设备发现、权限、读写、关闭。向上提交统一的字节事件及错误；一个时刻只运行一个调试会话。TCP 与 UDP 均提供客户端和监听模式。TCP 是字节流，界面不把一次读取当成完整应用报文。
- **会话控制器**：串行处理连接、断开、发送和重连请求；用会话代数丢弃旧连接的迟到事件。拔线、蓝牙离线、网络关闭都进入可见的已断开/错误状态，读写任务在关闭时取消。自动重连只针对 TCP 客户端，且由用户显式开启；硬件连接重新授权由用户操作。
- **记录与协议**：记录每次收发的时间、方向、连接类型和原始字节，展示时切换 HEX/文本。原始字节不因文本解码而改变。配置和最近日志保存在应用私有存储，日志有明确容量上限和导出入口；持久化在后台执行，不阻塞收发界面。
- **界面**：手机主屏始终可见连接状态、接收记录和发送区；设备与参数从连接面板选择，Modbus 模板从发送区打开。平板在宽屏并排显示连接设置与记录/发送区。收发、权限申请和错误提示都使用中文，不要求用户先理解 Android 权限名称。

USB 使用 Android USB Host 权限和 `usb-serial-for-android` 驱动，首版覆盖该库支持的常见 CDC ACM、CH34x、CP210x、FTDI、PL2303 设备；不承诺所有 USB 设备。经典蓝牙连接已配对或扫描到的 SPP 设备。BLE 没有统一串口协议：内置 Nordic UART Service 配置，并允许设置服务 UUID、写入特征 UUID、通知特征 UUID 与写入方式；设备仍须提供兼容的 GATT 特征。BLE 发送按协商后的有效负载长度分片，接收保留通知原始顺序。Android 12 及以上按平台要求申请蓝牙权限。首版连接只需在应用可见时保持；后台持续采集另列为后续需求。

## Modbus 模板

模板包含 03 读保持寄存器、04 读输入寄存器、06 写单寄存器和 10 写多寄存器。用户可改站号、起始地址、数量和值，先预览生成的 HEX 再发送。USB、SPP、BLE 使用 RTU 帧并计算 CRC16（低字节在前）；TCP 使用 MBAP 头和事务编号。UDP 保留通用原始报文发送，不自动套用 Modbus TCP。地址在界面按协议的零基地址输入，并给出示例，避免把 `40001` 当成线上地址。模板的输入范围、功能码长度和字节序使用与 Go `core` 对照的固定测试向量验证。

## APK 更新与发布

Android 版沿用现有 Gitee 优先、GitHub 备用的正式发布源，只选择安卓版 APK。检查有新版本后显示版本与说明；下载到应用私有缓存，要求发布说明或校验清单包含该 APK 的 SHA256，校验成功才调用 Android 系统安装界面。校验缺失、版本回退、下载中断或签名不匹配时不安装，并给出可理解的提示。安装未知来源权限由系统按需引导，应用不执行静默安装。

APK 的 application ID 固定，`versionCode` 递增，`versionName` 对应发布标签。所有可更新的 APK 必须由同一发布密钥签名；密钥和口令不进仓库。若用户已有密钥，使用现有密钥；否则在交付发布版前创建并备份专用密钥。CI 仅在签名材料已安全配置时产出可更新的正式 APK，且仍遵循现有手动发布流程。首版可先产出本地测试 APK。

## 验收与限制

- 桌面端：现有全套测试、`go vet ./...`、核心 race 检查通过；任何发现并修复的缺陷有针对性回归检查。没有真机证据时不声称修复了硬件兼容问题。
- Android 网络：模拟器或真机与本地 TCP/UDP 测试端点双向收发；切换连接、断开和异常关闭后无重复回调或旧会话数据混入。
- Android 设备：手机真机分别用一款受支持 USB 转串口、一款 SPP 设备和一款 BLE UART 设备验证权限、收发和拔线/离线；平板或平板模拟器验证宽屏布局。未取得相应硬件时明确记录未实测项。
- Modbus：RTU/TCP 模板输出与固定测试向量一致，错误参数无法发送，发送前能查看实际字节。
- 更新：使用同一密钥签名的旧版/新版 APK 验证升级，校验失败和不可信下载源不能进入安装步骤。

首版不包含桌面版的 AI、HTTP 工作区、虚拟串口、串口网络透传、后台持续采集或全部 BLE 厂商私有协议；这些功能不影响上述基本调试流程。
