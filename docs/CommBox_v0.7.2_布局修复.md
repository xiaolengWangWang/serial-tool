# CommBox v0.7.2 布局修复

## 修复内容

- 数据选择按钮改为原生 NSStackView 操作行，解决“反选”和“分析选中数据”控件相交；详情与统计各占独立区域。
- 发送格式、间隔、历史、收藏和发送按钮使用布局约束，消除 NSTabView 内容边距和不同缩放规则造成的重叠。
- 使用一致的初始布局尺寸构建控件，再挂到窗口；左侧连接参数保持顶部对齐且内部坐标稳定，放大后切换模式不会与连接状态/历史交叉。
- HTTP 模式只显示一个 URL 标签。
- 分析区域使用纵向布局，统计明确分行，结果区域随窗口高度扩展。

## 本次补充

- 分析中心默认隐藏，通过顶部“分析中心”按钮展开/收起。最小窗口为 1040×700；窄窗口展开分析时增加宽度，缩窄时自动收起，优先保留数据区。
- 发送区减小固定高度、详情区保持可滚动，释放更多表格空间。默认窗口与放大窗口的连接参数均采用紧凑表单，按模式隐藏整组字段。
- 筛选下拉明确为“全部方向 / 全部类型 / 全部长度 / 全部时间”，搜索框输入即筛选，重置统一恢复全部条件。
- 筛选、重置和刷新按报文本身保留选择，不把旧行号转移到其他报文。全选与反选只操作筛选后的可见记录。
- “分析选中数据”统一进入分析中心，统计所有选中报文；详细展开最多 20 条，明确说明未展开数量，不再只分析首条。

## 数据库本地分析

入口：顶部“数据库分析”，或分析中心 → “分析数据库…”。选择捕获文件、起止时间（本地时间）、方向和最近 100 / 500 / 2000 条候选记录，点击“开始本地分析”。

- 仅查询数据目录下已有的 `serial-data-*.sqlite3`；不接受路径跳转或符号链接，不修改数据库、不执行迁移。
- 只读事务提供一致快照。筛选范围内的全部记录统计 RX/TX 数量和字节数，断开事件不计入通信报文，普通发送和虚拟串口发送均归为 TX。
- 按时间选取最近的候选记录，再正序展示。负载上限为 8 MiB，超限时不截断单条报文，报告列出各类省略数量。
- 最多详细解析 20 条完整 `raw_data`，不使用显示截断内容。TCP、UDP、串口复用本地解析器；单条存档不保证正好是一帧，解析为候选结果，不推断完整请求响应匹配。
- 查询在后台运行，SQL 查询超时 30 秒；无联网、无 AI 调用。AI 入口仍仅针对界面明确选择的实时数据，不会自动上传数据库。
- 数据库报告中的统计针对所选文件和时间范围，不包含其他捕获文件。

## 验证

`desktop/layout_check.m` 检查真实 AppKit 控件的 alignment rect，相交或越出容器时返回非零退出码。

```sh
go build -o /tmp/commbox-layout-check ./desktop
check_dir=$(mktemp -d /tmp/commbox-layout-check-XXXXXX)
COMMBOX_LAYOUT_CHECK_DIR="$check_dir" /tmp/commbox-layout-check
```

检查尺寸为 1040×700、1280×700、1600×900、1920×1080、恢复 1280×700；分别测试分析中心隐藏/展开状态，每次尺寸变化后依次切换五种工作模式和两个发送页签（窄窗口自动收起分析中心）。同时验证数据库选项表单、筛选、保留选择、全选/反选、选中报文分析和数据表可视高度。测试不建立设备连接或调用 AI，输出控件树的 PNG 预览。系统合成的页签装饰在离屏缓存图中可能呈黑色，不能代替完整屏幕截图验收。

早期修复前该检查复现 110 次相交；现扩展为 100 个布局组合。该检查不验证物理串口设备或 AI 诊断正确性。

数据库解析回归位于 `internal/wincore/database_analysis_test.go`，覆盖混合时区、时间/方向过滤、原始负载、空数据、条数/字节上限、只读属性、路径校验和损坏 schema。运行 `go test -race ./...` 检查核心收发与并发行为；发布产物由对应标签的干净源码构建，仅提供 macOS 通用应用和 Linux amd64 命令行程序。
