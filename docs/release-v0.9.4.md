# CommBox v0.9.4

Windows x64，解压后运行 `CommBox.exe`。发布包附带 VirtualCOM v0.2.0 的图形界面和命令行，无需安装虚拟串口驱动。

## 本版变化

适配小屏和高缩放比：主窗口不再越出屏幕，发送区的报文框不再被挤小。

- 1600×900 @150%、1366×768 @125%、1920×1080 @175% 等设置下，屏幕可用区域只有约 1024×552 到 1097×569（按 100% 折算），原来的窗口最小尺寸放不进去，底部发送区被任务栏挡住，报文框有时只剩一两行。现在窗口始终放在可用区域内，报文框至少显示 4 行，数据表至少 3 行。
- 数据 / 日志由标签页改为「数据监控」标题右侧的一组切换按钮，省下标签条一整行。发送结果提示移到定时发送那一行的右侧，过长时显示省略号，鼠标悬停可看全文。
- 屏幕放不下默认尺寸时，窗口高度用满可用区域，宽度仍留出和其他窗口并排的余地。1920×1080 @150% 下数据表可显示约 10 行。
- 默认尺寸下报文框从 5 行增加到约 6 行，数据表约 16 行；中间的分隔条仍可拖动调整。
- 多显示器时按窗口所在的那块屏幕计算可用区域。

## 使用

先运行 `VirtualCOM-GUI.exe` 创建一对端口并保持运行，再打开两个 CommBox 窗口，分别连接两端。命令行使用 `CommBox-CLI.exe -list` 查看端口、`-port COM号` 打开。

## 验证与边界

- 全量 Go 与 Windows GUI 回归测试通过；发布产物逐项校验 PE 头、构建来源 commit、版本资源和压缩包内容。
- 新增布局测试：在真实窗口上模拟 9 种屏幕与缩放组合（从最紧的 1024×552 到 1920×1080 @100%），检查窗口不越出可用区域、报文框至少 4 行、数据表至少 3 行、控件不重叠不裁切。
- 测试机当前为 100% 缩放，其他缩放比按折算后的尺寸模拟，没有在 125%、150%、175% 的真实显示设置下逐一验收。控件下限随缩放等比放大，并为字高取整留了余量。
- 可用区域低于约 966×540（按 100% 折算）时窗口仍放不下，Windows 标准缩放档不会出现这种情况。
- VirtualCOM 适配的边界与 v0.9.0 相同：只提供字节流端口，波特率、数据位、校验、停止位和控制信号不生效，未适配的第三方串口软件仍不兼容。
- VirtualCOM 必须保持运行并与 CommBox 位于同一用户登录会话；退出后端口会移除。Windows 10 和长时间运行尚未验收。
- 程序未做商业代码签名。
