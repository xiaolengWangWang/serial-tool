# VirtualCOM V1 功能规格

日期：2026-09-20

状态：功能规格草案，待审阅；尚未进入实现

依据：用户提供的 VirtualCOM 功能清单与主界面草图

## 1. 产品目标与范围

VirtualCOM 用于在 Windows 上创建和管理稳定的虚拟串口对。两个普通串口软件分别打开一对端口，即可双向通信，例如：

```text
CommBox.exe → COM10 ⇄ COM11 ← ModbusSlave.exe
```

用户只需要理解五类操作：**创建、删除、管理、查看状态、故障诊断**。Windows 串口 API、异步读写、控制信号和缓存等待属于自动工作的兼容能力，不作为普通用户必须填写的配置。

本规格以用户最新要求为准：V1 只包含虚拟串口对。此前讨论的 COM ↔ TCP 映射移出 V1。

| V1 包含 | V1 不包含 |
| --- | --- |
| 虚拟串口对的创建、配置、状态、诊断与驱动管理 | 串口助手、手动 HEX 收发、Modbus 解析 |
| Windows 10 x64、Windows 11 x64 | TCP/UDP 转串口、物理串口转发、AI 分析 |
| 重启后保留端口，退出 GUI 后继续通信 | 物理线路电气特性与传输速率仿真 |

以下清单中的“必备”表示 V1 交付要求，不表示当前已经实现。本文不决定驱动框架、进程划分、接口协议或构建方式。

## 2. V1 功能清单

### 2.1 虚拟串口对

| 功能 | V1 | 用户可见行为 |
| --- | --- | --- |
| 创建串口对 | 必备 | 一次创建两个相互连接的端口，如 COM10 ⇄ COM11 |
| 删除串口对 | 必备 | 以整对为单位删除，明确显示将删除的两个端口 |
| 创建多组串口对 | 必备 | 同时管理多对端口，每对都有独立配置与状态 |
| 自动选择空闲 COM 号 | 必备 | 默认提供两个可用且互不重复的 COM 号 |
| 手动指定 COM 号 | 必备 | 用户分别填写两端编号，提交前检查冲突 |
| 修改 COM 号 | 必备 | 可修改其中一端或两端，保留配对关系 |
| 启用 / 禁用串口对 | 必备 | 禁用后保留配置，重新启用后恢复可用状态 |
| 重启虚拟串口 | 必备 | 对整对执行重启，恢复原 COM 号与配对关系 |

### 2.2 端口状态

| 功能 | V1 | 用户可见行为 |
| --- | --- | --- |
| 空闲 / 使用中 / 禁用 / 异常 | 必备 | 两个端口分别显示自己的状态 |
| 显示端口占用程序 | 必备 | 能获取时显示程序名称；不能获取时明确显示“无法获取” |
| 显示占用进程 PID | 必备 | 在端口详情显示，不因获取失败将使用中误报为空闲 |
| 刷新 COM 状态 | 必备 | 刷新端口、占用、配对关系和驱动状态 |

状态说明：

| 状态 | 含义 |
| --- | --- |
| 空闲 | 端口已启用、设备正常，当前没有串口软件打开 |
| 使用中 | 端口已被串口软件打开；不等同于正在传输数据 |
| 禁用 | 用户主动禁用了该串口对 |
| 异常 | 端口、配对或驱动存在问题；展示可读原因与诊断入口 |

刷新期间保留上一次状态并显示刷新进度。刷新失败时标注“状态获取失败”和最近更新时间，不能用过期状态冒充当前结果。

### 2.3 串口通信

| 功能 | V1 | 要求 |
| --- | --- | --- |
| COM A → COM B | 必备 | A 写入的数据可由 B 读取 |
| COM B → COM A | 必备 | B 写入的数据可由 A 读取 |
| 全双工同时收发 | 必备 | 两个方向可以同时传输 |
| 大数据连续传输 | 必备 | 连续传输时不截断、不乱序、不重复 |
| 多组串口互不干扰 | 必备 | 数据仅进入其配对端口 |

传输的是连续字节流，不承诺一次写入恰好对应一次读取。第三方软件无需使用 VirtualCOM 专用通信协议。

### 2.4 串口参数兼容

| 功能 | V1 | 要求 |
| --- | --- | --- |
| 波特率 | 必备 | 支持第三方软件设置与读取 |
| 数据位 5 / 6 / 7 / 8 | 必备 | 支持 Windows 合法参数组合 |
| None / Odd / Even / Mark / Space 校验 | 必备 | 支持设置与读取 |
| 1 / 1.5 / 2 停止位 | 必备 | 支持 Windows 合法参数组合，非法组合明确报错 |
| Read / Write Timeout | 必备 | 按应用设置的读写超时行为工作 |
| 自定义波特率 | 必备 | 支持有效的非预设波特率数值 |

参数由使用端口的串口软件设置，VirtualCOM 可在详情中展示当前值。创建串口对时不要求用户填写波特率、数据位、校验或停止位。参数兼容不代表按物理串口线速限速，也不模拟波特率不匹配产生的电气错误。

### 2.5 控制信号兼容

| 功能 | V1 | 要求 |
| --- | --- | --- |
| RTS / CTS | 必备 | 使用固定的交叉连接关系：一端 RTS 对应另一端 CTS |
| DTR / DSR | 必备 | 一端 DTR 对应另一端 DSR |
| DCD | 必备 | 一端 DTR 同时对应另一端 DCD |
| BREAK | 必备 | 支持设置、清除及配对端的相应状态 / 事件 |
| 硬件流控 | 必备 | 尊重应用配置的 CTS / DSR 等发送控制条件 |

V1 使用固定配线规则，两端对称，不要求普通用户绘制配线或手动切换信号。详情可只读查看信号状态。

### 2.6 Windows API 兼容

| 能力 | V1 |
| --- | --- |
| CreateFile / CloseHandle | 必备 |
| ReadFile / WriteFile | 必备 |
| 同步 IO | 必备 |
| Overlapped 异步 IO | 必备 |
| CancelIo / CancelIoEx | 必备 |
| SetCommState / GetCommState | 必备 |
| SetCommTimeouts / GetCommTimeouts | 必备 |
| SetCommMask / WaitCommEvent | 必备 |
| PurgeComm | 必备 |
| ClearCommError | 必备 |

这是兼容性验收清单，不对应主界面按钮。端口被占用、读写超时、取消操作等结果应能被普通 Windows 串口软件正确识别。

### 2.7 数据缓存

| 功能 | V1 | 要求 |
| --- | --- | --- |
| 独立 RX / TX 缓冲区 | 必备 | 每个端口的收发缓存和每组配对相互独立 |
| 缓冲区满时等待 | 必备 | 等待可用空间，遵守写超时与取消要求，不直接静默丢弃 |
| 缓冲区使用量显示 | 必备 | 在详情中展示各端收发缓存的已用量和容量 |
| 清空 Buffer | 必备 | 在详情中提供清空操作，明确说明会丢弃相应待收发数据 |

读写超时、取消、主动清空或端口重启后，必须能区分正常完成、部分完成与未完成数据。不得将未完成的传输计为全部成功。

### 2.8 数据统计

| 功能 | V1 | 显示位置 |
| --- | --- | --- |
| A → B 字节数 | 必备 | 主界面与详情 |
| B → A 字节数 | 必备 | 主界面与详情 |
| Read / Write 次数 | 必备 | 详情 |
| Pending IO 数量 | 必备 | 详情中的高级信息与诊断报告 |
| 错误统计 | 必备 | 详情；异常时主界面提示 |
| 清空统计 | 必备 | 串口对详情 |

统计约定：

- 主界面两端分别显示 TX，表示该端已成功提交发送的字节数；不把它标为对端软件已经读取的字节数。
- 详情分别列出两端 TX / RX、读写次数、待处理请求和错误，避免把写入与读取混为一项。
- 统计从本次系统启动或该串口对创建时开始，GUI 退出、重新打开不会清零；系统重启后重新计数。
- 用户可清空单对统计。清空统计不清空数据缓存，不中断通信。

### 2.9 诊断

| 功能 | V1 | 报告内容 |
| --- | --- | --- |
| 检查驱动状态 | 必备 | 是否可用、版本和错误信息 |
| 检查 COM 设备状态 | 必备 | 端口是否存在、启用状态和异常 |
| 检查配对关系 | 必备 | 两端是否完整、编号是否一致或冲突 |
| 检查端口占用 | 必备 | 占用状态、程序和 PID，或无法获取的原因 |
| 检查 Buffer / IO 状态 | 必备 | 缓存使用量、待处理请求和错误统计 |
| 一键复制诊断报告 | 必备 | 复制可直接发送给维护人员的文本报告 |

诊断默认只检查和报告。修复、清空、重启或删除由用户另行执行。报告包含检查时间、软件版本、系统版本、检查结果与建议操作。

### 2.10 驱动管理

| 功能 | V1 | 用户可见行为 |
| --- | --- | --- |
| 查看驱动状态 | 必备 | 主界面显示状态，点击后查看详情 |
| 查看驱动版本 | 必备 | 驱动管理页展示 |
| 安装驱动 | 必备 | 未安装时给出明确入口和安装结果 |
| 修复 / 重新安装驱动 | 必备 | 尝试恢复可用状态，说明对现有串口对的影响 |
| 卸载驱动 | 必备 | 列出受影响的串口对，由用户确认后执行 |

驱动未就绪时，创建按钮显示不可用原因。操作失败时提供可读错误和诊断入口，不显示虚假的安装或修复成功。

### 2.11 系统功能

| 功能 | V1 | 要求 |
| --- | --- | --- |
| Windows 10 x64 | 必备 | 纳入真实系统验收 |
| Windows 11 x64 | 必备 | 纳入真实系统验收 |
| 系统重启后继续存在 | 必备 | 恢复原 COM 号、配对关系和启用 / 禁用状态 |
| GUI 退出后继续工作 | 必备 | 已运行的串口软件仍能通过虚拟串口通信 |
| Windows 设备管理器可见 | 必备 | 每个虚拟 COM 口均可识别，名称可与工具内对应 |

系统重启后由第三方软件重新打开端口；不承诺恢复已经结束的第三方进程或重启前未读取的数据。

### 2.12 日志

| 功能 | V1 | 用户可见行为 |
| --- | --- | --- |
| 软件运行日志 | 必备 | 记录创建、修改、启停、删除及操作失败 |
| 驱动错误日志 | 必备 | 可在诊断中查看相关错误及发生时间 |
| Debug 日志 | 必备 | 在诊断高级选项中按需开启，默认关闭 |

主界面不展示滚动调试日志。日志需有大小限制，避免长期运行持续占满磁盘。

## 3. 主界面

```text
VirtualCOM                                      驱动状态：正常

                                                [＋ 创建串口对]

┌──────────────────────────────────────────────────────────────┐
│ COM10 · 使用中                         使用中 · COM11        │
│ CommBox.exe                            ModbusSlave.exe       │
│ TX 125 MB                              TX 86 MB              │
│                                           [详情] [更多 ⋯]    │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│ COM20 · 空闲                           空闲 · COM21          │
│ TX 0 B                                 TX 0 B                │
│                                           [详情] [更多 ⋯]    │
└──────────────────────────────────────────────────────────────┘

2 个串口对 · 4 个虚拟端口                       [诊断] [刷新]
```

布局规则：

- 一张卡片对应一对串口，两端信息对称展示；用清晰的双向连接标识表达配对。
- 顶部突出“创建串口对”，驱动状态可点击进入驱动管理。
- 卡片默认展示端口号、状态、占用程序和 TX 字节数。PID、RX、缓存、参数和信号进入详情查看。
- “更多”包含修改 COM 号、启用 / 禁用、重启、删除；删除使用文字标识，避免不明确的图标。
- 底部显示串口对数量与虚拟端口总数，提供全局诊断和刷新。
- 无串口对时展示空状态及创建入口。端口异常同时显示文字原因，不只依赖颜色。

主界面不增加串口发送框、HEX 面板、协议分析页或网络配置项。

## 4. 关键操作流程

| 操作 | 正常流程 | 失败或受限时的表现 |
| --- | --- | --- |
| 创建 | 默认自动编号 → 可切换手动编号 → 创建 → 展示完整串口对 | COM 冲突时指出具体编号；不能将只创建了一端显示为成功 |
| 修改 COM 号 | 查看两端编号 → 修改 → 检查 → 保存 | 任一端正在使用时阻止修改，展示占用信息；失败后保留或明确恢复原配置 |
| 禁用 | 选择禁用 → 展示影响 → 禁用整对 | 任一端正在使用时提示先关闭占用程序 |
| 启用 | 选择启用 → 检查设备和编号 → 恢复可用 | 编号冲突或设备异常时报告原因，不自动改成另一组编号 |
| 重启 | 展示会中断通信并清除待收发数据 → 重启整对 | 任一端正在使用时提示先关闭占用程序 |
| 删除 | 展示两个 COM 号 → 用户确认 → 删除整对 | 任一端正在使用时阻止删除；部分失败时保留可见的异常记录与修复入口 |
| 查看详情 | 显示两端状态、占用、参数、信号、统计和缓存 | 信息无法获取时明确标注，不能用 0 或“空闲”代替未知 |
| 故障诊断 | 执行检查 → 展示原因和建议 → 可复制报告 | 单项检查失败仍保留其他检查结果 |

修改、禁用、重启和删除都不主动结束第三方进程。创建或删除正在进行时，防止重复提交同一操作。

## 5. 兼容能力与普通操作的边界

| 普通用户主动操作 | 应自动工作的兼容能力 |
| --- | --- |
| 选择 COM 号、创建或删除配对 | CreateFile、CloseHandle、同步 / 异步读写 |
| 启用、禁用、重启 | 超时、取消、串口事件、错误报告 |
| 查看状态、复制诊断 | 缓冲区等待、双向通信、组间隔离 |
| 在详情中按需清空缓存或统计 | RTS / CTS、DTR / DSR、DCD、BREAK、硬件流控 |

兼容能力可以有只读状态和诊断信息，但不变成创建串口对前的必填设置。IOCTL 等实现细节不出现在普通用户操作流程中。

## 6. V1 验收标准

以下为功能验收，性能数值在具备测试环境后记录实测结果，不预先宣称吞吐量或延迟。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| F01 | 自动、手动创建及编号冲突 | 创建后两端完整可见；重复、冲突、非法编号有明确反馈 |
| F02 | 修改编号与生命周期操作 | 修改、启停、重启、删除符合第 4 节约定；设备列表与工具一致 |
| F03 | 第三方软件通信 | 使用至少两种独立的串口客户端验证双向、全双工及重复打开关闭 |
| F04 | 连续大数据 | 用包含任意字节值的数据连续传输，核对长度和内容，无丢失、乱序、重复 |
| F05 | 多组并行 | 多组同时传输不同内容，数据、信号和统计互不串组 |
| F06 | 缓存满与恢复 | 接收方暂停读取后，发送方按超时或取消约定等待；恢复读取后继续传输 |
| F07 | Windows API 与参数 | 第 2.4、2.6 节逐项有独立验证，覆盖事件通知、超时、取消与清空 |
| F08 | 控制信号与流控 | 两个方向的固定配线、信号事件、BREAK 和流控行为符合第 2.5 节 |
| F09 | GUI 退出与系统重启 | 退出 GUI 不影响通信；重启系统后编号、配对和启用状态恢复 |
| F10 | 占用与统计 | 使用中状态与实际打开情况一致；程序 / PID 无法获取时有明确提示；统计口径一致 |
| F11 | 异常与诊断 | 驱动异常、端口缺失、占用或操作失败能被定位；诊断报告可复制 |
| F12 | 驱动管理 | 在干净系统验证安装、修复和卸载，结果可确认，现有端口影响有说明 |
| F13 | 系统兼容 | Windows 10 x64 与 Windows 11 x64 分别完成验收；记录具体系统版本 |
| F14 | 长时间运行 | 连续收发、反复创建删除、读写取消和界面开关后，无持续资源增长、卡死或异常退出 |

没有完成真实系统与第三方串口软件验收的项目，不标记为已支持。源码编写或单项测试通过不等同于 V1 已交付。
